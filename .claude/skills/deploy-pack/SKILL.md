# 增量部署打包（deploy-pack）

把当前项目的变动文件打包为可直传服务器部署的 ZIP。最终交付物是一个 ZIP，内含：

1. **所有变动文件**（保持项目原始目录结构）
2. **`_deploy/` 目录**：
   - `filelist.txt` — 变动文件清单（ZIP 内所有业务文件的相对路径，deploy.bat 的操作依据）
   - `deploy.bat` — 在服务器上运行：备份将被覆盖的旧文件 → 二次确认 → 覆盖部署
   - `restore.bat` — 回滚：把备份目录中的旧文件恢复回项目
   - `verify.bat` — 部署后核对：逐文件比对包内与项目中的字节大小并打印时间戳
   - `部署说明.txt` — 服务器操作步骤

## 使用流程

### 第 1 步：确定变动文件清单

```bash
git status --porcelain   # 已修改(M) + 未跟踪(??)
```

在此基础上做两件事：

1. **gitignore 检查（双重保障）**：对每个文件跑 `git check-ignore -q <path>`，被忽略的文件**必须包含**——gitignore 只影响 git 提交，不影响部署需求（如 `lesson/config/api_permissions.yaml` 不进 git，但服务器启动种子依赖它）。`pack_changes.py` 另有白名单兜底：`IGNORED_INCLUDE_WHITELIST` 中的文件即使清单遗漏也会自动纳入并打印提示。注意白名单只收"启动时只做种子、覆盖无运行时风险"的文件；服务器私有配置（setting.local.json、lesson.yaml 等）严禁加入。
2. **与用户确认范围**：默认排除 `tests/`、`docs/`（服务器运行不需要），排除与本任务无关的杂项改动（如用户遗留的其他文件修改）。把最终清单列给用户确认后再打包。

### 第 2 步：写清单文件并运行打包脚本

把确认后的文件清单（每行一个仓库相对路径）写入临时文件，然后：

```bash
python3 <skill目录>/scripts/pack_changes.py \
  --files /tmp/deploy_files.txt \
  --out <项目根>/deploy_<主题>_<日期>.zip \
  --note "本次变更内容一句话描述"
```

脚本会：校验所有文件存在 → 按原始目录结构写入 ZIP → 附 `_deploy/` 四件套（deploy.bat/restore.bat 从本 skill 的 `scripts/` 目录取）。

### 第 3 步：交付

给用户 ZIP 路径 + 服务器操作摘要（见下）。提醒：

- **数据库文件绝不能放进部署包**（服务器启动时自动迁移）
- 服务器操作：解压 ZIP → **进入 _deploy 目录**运行 `deploy.bat <项目根目录>` → 按提示确认部署 → 重启后端（deploy.bat 以自身位置的上一级作为包根定位业务文件）
- 回滚：运行备份目录里的 `restore.bat <备份目录> <项目根目录>`

## deploy.bat 行为（服务器端，Windows）

1. 接收项目根目录参数（或交互输入），校验存在
2. 读取 `filelist.txt`，逐个检查服务器上是否存在旧文件：存在 → robocopy 备份到 ZIP 解压目录下的 `backup_时间戳/`（保持目录结构）
3. 生成回滚说明，**二次确认**后才执行覆盖
4. 覆盖部署 ZIP 内的新文件到项目根目录
5. 打印后续步骤（重启后端、管理页配置等）

## 注意事项

- **BAT 编码必须是 GBK/ANSI（CRLF），禁止 UTF-8 + chcp 65001**（pack_changes.py 打包时对所有 .bat 自动转换，新增 BAT 无需手工处理）：cmd 在批处理中途切代码页会按旧字节偏移重解析文件，中文字符导致命令被截断（曾出现 `'ploy.bat' is not recognized`）。GBK 在中文 Windows 上原生显示，无需 chcp
- **复制用 `copy /y` + 复制后核对文件大小，不用 robocopy**：robocopy 默认按时间戳跳过"目标较新"的文件，旧部署留下的文件时间戳常比新包内的还新，导致假成功（即使加 /IS /IT 也存在环境差异风险）。`copy /y` 无条件覆盖、无时间戳逻辑；复制后比对源/目标文件大小（`%%~z`），以实测为准报告成败
- **每次只打包自上次部署以来的增量**：以 git 未提交改动（`git status --porcelain`）+ 用户确认为准，不要沿用上次的全量清单；服务器上已有旧版时，全量包会产生大量无意义的"备份"
- **路径拼接必须显式写分隔符**：`"%ROOT%!REL!"`（缺 `\`）会拼成 `...honghuanghoufrontend\...` 这种目录——已导致文件被写到错误位置且大小校验自洽通过、完全无法察觉。改完脚本要扫描所有 `ROOT` 变量后是否紧跟 `\`
- **禁止用 `%%~dpF` 解析相对路径**：bat 运行目录 ≠ 项目根目录，`for %%F in ("相对路径")` 的 `%%~dpF` 会拼上 cmd 当前目录，产生 `D:\root\C:\Users\...\_deploy\lesson\...` 垃圾路径，robocopy 全部报错。正确做法：统一走 `:copy_one` 子程序，传入**绝对**源/目标文件路径，`%~f1` 强制解析，`%~dp1` 取目录、`%~nx1` 取文件名
- robocopy 退出码 0-7 均为成功，≥8 为失败需报错；它会自动创建目标子目录，但脚本中仍显式 `mkdir` 目标目录兜底
- 每次部署的 ZIP 都是独立自包含的（旧文件备份落在解压目录里），可多次叠加使用
- 若变动包含**删除**的文件，脚本与 bat 均不处理删除——需要时在部署说明中人工提示
