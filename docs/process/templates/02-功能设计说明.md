# 功能设计说明（给使用者审核）

> **给使用者**：这份说明告诉你「这个功能做好后长什么样、你怎么用」。请仔细看，**看不懂的地方一定要问**，确认没问题了我们才开始做。你的确认是开发的"开工令"。
>
> **给开发者**：本文全程用通俗语言，不出现数据库、接口、字段等技术词。多举例子、多写操作步骤，必要时贴草图/截图。

## 1. 这个功能帮你解决什么？

> 一两句话，呼应需求卡片里的问题。



## 2. 做好后，你在系统里会看到什么变化？

> 描述界面上的变化：哪个菜单/页面多了什么按钮、什么列表、什么信息。

（例：在"监考安排"页面右上角，会多一个【发送通知】按钮。）



## 3. 你具体怎么用？（操作步骤）

> 一步一步写，让使用者能照着做。

1. 打开……
2. 点击……
3. 选择……
4. 看到……说明成功了。



## 4. 举个例子

> 用一个真实的例子演示"之前 → 之后"。

**以前**：（怎么做、多麻烦）

**以后**：（怎么做、多省事）



## 5. 几个你会关心的问题

> 主动把使用者可能担心的点说清楚。

- **会不会影响现在已有的功能/数据？**：
- **谁能用、谁不能用？**：
- **出错了会怎样？**（如：通知没发出去会提示你，不会悄悄失败）
- **能不能撤销/重来？**：



## 6. 这次不做的部分

> 明确边界，避免使用者以为"顺便也做了"。

（例：这次只支持微信通知，不做短信通知。）
