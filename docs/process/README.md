# 开发流程与模板

本目录定义「使用者提需求 → 开发者设计 → AI 开发 → 使用者验收」的协作流程及配套模板。

## 读什么

- **想了解流程**：读 [collaboration-workflow.md](collaboration-workflow.md)（核心规范，含完整流程与轻量通道）。
- **要开始一个新需求**：复制 `templates/` 下对应模板，按阶段逐个产出。

## 模板清单（按使用顺序）

| 模板 | 谁用 | 什么时候用 | 语言风格 |
|------|------|------------|----------|
| [01-需求卡片](templates/01-需求卡片.md) | 使用者填写 | 阶段①② 提需求、定验收标准 | 通俗，使用者看得懂 |
| [02-功能设计说明](templates/02-功能设计说明.md) | 开发者写、使用者审 | 阶段③④ 方案设计与审核 | 通俗，配例子和步骤 |
| [03-技术实现方案](templates/03-技术实现方案.md) | 开发者写 | 阶段③ 技术设计 | 技术，给 AI 看 |
| [04-AI开发任务书](templates/04-AI开发任务书.md) | 开发者整合后交给 AI | 阶段⑤ 开发 | 结构化，AI 可直接执行 |
| [05-验收测试清单](templates/05-验收测试清单.md) | 使用者验收 | 阶段⑥ 验收 | 通俗，照着逐项试 |

## 配套

- 具体需求实例与状态：见 [`docs/requirements/`](../requirements/README.md)（需求台账）。
- 已有功能清单（通俗）：见 [`docs/user-guide/feature-catalog.md`](../user-guide/feature-catalog.md)。

## 两条通道速查

- **轻量通道**（修 bug、改文案、小优化）：提需求 → 开发 → 验收。只需说清"现在怎样、期望怎样"。
- **完整流程**（新功能、新业务规则、权限变化）：走满 6 阶段，产出全套文档。
- **红线**：无论哪条通道，验收标准先于开发明确，上线前必须实测。
