# 需求台账

> 每个需求一个目录，存放该需求从提出到验收的全部产出物（需求卡片、设计说明、技术方案、验收记录等）。
> 本文件维护**状态总览**，新需求进来就在下表加一行。

## 需求编号规则

`REQ-年份-序号`，如 `REQ-2026-001`。目录命名：`REQ-2026-001-简短名称/`。

## 状态说明

| 状态 | 含义 | 对应流程阶段 |
|------|------|--------------|
| 待澄清 | 需求已提出，待确认场景和验收标准 | ①② |
| 设计中 | 正在出功能设计说明和技术方案 | ③ |
| 待审核 | 设计说明待使用者确认（可能多轮） | ④ |
| 开发中 | 已确认，AI 开发中 | ⑤ |
| 待验收 | 开发完成，待使用者验收 | ⑥ |
| 已上线 | 验收通过并上线，功能清单已更新 | 完成 |
| 已搁置 | 暂不开发（注明原因） | — |
