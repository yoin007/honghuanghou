# AI 开发任务书：监考工作量主副监权重折算

## 一、背景（为什么做）

监考工作量报表当前主监、副监完全同权（各计 1 场、整场时长），与学校实际考核口径不符。教务需要能在系统里配置主/副监权重折算工作量，并要求主副监原始场次分开统计、权重为 0 也照常计数。

## 二、需求（做什么）

1. 新增全局权重配置（主监权重、副监权重，默认各 1.0，0~10），存 invigilation.db 新表 `invigilation_config`，模块导入时幂等建表。
2. 新增 `GET/PUT /api/invigilation/config`，仅 jiaowu/admin；PUT 校验 0~10；yaml 同步权限条目。
3. 报表改造：主监场次、副监场次按原始计数分列（与权重无关）；折算列 = 权重 × 场次、权重 × 时长；权重为 0 时折算归零但原始场次照常。
4. 脏数据口径：时间格式非法（strftime 得 NULL）的行从所有场次列和时长列同时排除。
5. 前端：监考安排页工具栏加【权重设置】按钮 + 弹窗（0~10，步进 0.1）。
6. 性能：`/export`、`/report` 端点 `async def` → 同步 `def`（进线程池，避免阻塞事件循环）。

**明确不做**：权重不按考试项目区分；不做补贴金额计算；不改通知/提醒逻辑。

## 三、项目约束（必须遵守）

- 技术栈：后端 FastAPI + SQLite，前端 Vue 3 + Element Plus + Vite。
- 权限：新增 API 必须同步 `lesson/config/api_permissions.yaml`；DB 为权限权威，启动自动落库，禁止手工 SQL。
- 数据库：schema 走幂等自动迁移，严禁覆盖服务器数据库文件。
- 性能：阻塞操作不得在 `async def` 端点内执行；重活端点用同步 `def`。
- 代码：Python PEP 8、前端 ESLint；外科手术式修改。
- 验证：改完必须跑测试与 build；不许注释掉报错求跑通。
- 部署：deploy-pack 增量打包；不要自动 git push。

## 四、技术方案要点

- 配置表：`invigilation_config(key TEXT PRIMARY KEY, value TEXT NOT NULL)`，键 `primary_weight`/`assistant_weight`；读取对缺失/非法/越界回落 1.0。
- 报表 CTE：主副 `UNION ALL`，每行带 role/weight/duration_minutes；weight 用参数占位不拼接 SQL；原始场次按 role 条件计数，折算按 weight 求和；`duration IS NULL` 行全列排除。
- 权限 yaml 条目：`/api/invigilation/config`，http_method `*`，match_type exact，allowed_roles [jiaowu, admin]，min_level 10，action_type operate。
- 前端注意 httpClient 拦截器已解包一层，组件取 `res.data.xxx`。
