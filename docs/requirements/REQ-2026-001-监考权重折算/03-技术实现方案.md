# 技术实现方案：监考工作量主副监权重折算

## 基本信息

- **需求编号**：REQ-2026-001
- **关联文档**：《功能设计说明》v1（已通过审核）

## 1. 背景与目标

监考工作量报表（`GET /api/invigilation/projects/{id}/report`）原实现主副监同权（各计 1 场、整场时长）。目标：权重全局可配置（jiaowu/admin），同时支持主副监原始场次分开统计；权重为 0 时原始场次照常计数、折算列归零。

## 2. 现状与影响面

- 后端：`lesson/models/datas_api/invigilation.py`（报表端点 + 新配置端点 + 配置表）
- 前端：`frontend/src/views/InvigilationArrange.vue`（权重设置弹窗）、`frontend/src/api/modules/invigilation.js`
- 数据库：invigilation.db 新增 `invigilation_config` 表
- 影响的既有功能：无（仅报表算法与新增配置入口）

## 3. 数据模型

```sql
CREATE TABLE IF NOT EXISTS invigilation_config (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
-- keys: primary_weight / assistant_weight，值为字符串化 float
```

- 迁移方式：模块导入时 `_ensure_invigilation_config_schema()` 幂等建表（CREATE IF NOT EXISTS），不动服务器 DB。
- 读取兜底：`get_invigilation_weights()` 对缺失/非法/越界值回落默认 1.0。

## 4. API 设计

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | /api/invigilation/config | 读取当前权重 | jiaowu, admin |
| PUT | /api/invigilation/config | 更新权重（0~10 校验） | jiaowu, admin |

权限登记：`lesson/config/api_permissions.yaml` 新增 `/api/invigilation/config` 条目（http_method `*`、match_type exact、action_type operate），启动时缺失行自动落库。

## 5. 前端设计

- 工具栏新增【权重设置】按钮 → 弹窗（el-input-number ×2，min 0 / max 10 / step 0.1）。
- `invigilationApi.getWeightConfig/updateWeightConfig`；注意 httpClient 拦截器已解包一层，组件内取 `res.data.primary_weight`。

## 6. 关键逻辑与边界

- 报表 CTE：主监/副监 `UNION ALL` 打平，每行带 `role`（primary/assistant）、`weight`（参数占位，不拼接 SQL）、行内预计算 `duration_minutes`（strftime 秒差/60，格式非法 → NULL）。
- 原始场次：`SUM(CASE WHEN role='primary' AND duration IS NOT NULL THEN 1 ...)`，与权重无关。
- 折算：`SUM(CASE WHEN duration IS NULL THEN 0 ELSE weight END)` 与 `SUM(duration * weight)`；脏数据行（duration IS NULL）从所有列同时排除。
- 性能：`/export`、`/report` 端点由 `async def` 改同步 `def`，SQL + openpyxl 进 anyio 线程池，避免阻塞事件循环。
