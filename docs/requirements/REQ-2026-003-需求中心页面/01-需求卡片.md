## 1. 我想解决什么问题？

协作流程目前靠文档（docs/requirements/ 台账）维护，老师参与要走线下：不知道系统有什么功能、提需求靠微信转述、进度看不到。参与成本高，流程留痕分散。

## 2. 谁在什么情况下会遇到？

老师想提功能建议时；教务/开发者想看有哪些待处理需求时；老师想了解"系统都能干什么"时。

## 3. 我希望达到什么效果？

系统里有一个「需求中心」页面，包含：功能大厅（已有功能通俗展示）、提需求（表单提交）、需求跟踪（看自己的需求进度，教务/开发者看全部并管理状态）。

## 4. 怎样算"做好了"？（验收标准）

- [ ] 老师能在页面看到按功能域分组的已有功能清单（通俗语言）
- [ ] 老师能填表提交需求，提交后拿到编号，能看到自己的需求列表和状态
- [ ] 教务/管理员能看到全部需求，能更新状态并留痕（谁、何时、做了什么）
- [ ] 老师看不到别人的需求；管理动作有日志可查
- [ ] 提交的内容有校验，不会存进空数据
