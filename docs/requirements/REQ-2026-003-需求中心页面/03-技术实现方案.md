# 技术实现方案：需求中心页面

## 基本信息

- **需求编号**：REQ-2026-003
- **关联文档**：《功能设计说明》v1（已确认）

## 1. 背景与目标

把协作开发流程产品化：功能大厅（前端静态数据）+ 需求提交与状态跟踪（moral.db 新表）。

## 2. 数据模型（moral.db，幂等自动迁移）

```sql
requirement(id, title, problem, scenario, expectation,
            status DEFAULT 'pending', submitter_id, submitter_name,
            created_at, updated_at)
requirement_log(id, requirement_id, actor_name, action, note, created_at)
-- action: submit / status / comment；状态字典见 REQUIREMENT_STATUSES
```

## 3. API（router prefix /api/requirements，模块 requirements_api.py）

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| POST | /api/requirements | 提交需求 | 全员（teacher/cleader/g_leader/xuefa/jiaowu/admin） |
| GET | /api/requirements?scope=mine\|all | mine=自己的；all 仅 jiaowu/admin（代码双重校验） | 全员 / 管理端 |
| GET | /api/requirements/{id} | 详情+时间线（仅提交人或管理端） | 全员 |
| PUT | /api/requirements/{id}/status | 推进状态（yaml jiaowu/admin + 代码 `_is_manager` 双重校验） | jiaowu, admin |
| POST | /api/requirements/{id}/comments | 追加说明（提交人或管理端） | 全员 |

yaml：4 条条目（exact/pattern），http_method 各自明确；`_is_manager` 与 require_jiaowu 同口径。

## 4. 前端

- `frontend/src/views/RequirementCenter.vue`：el-tabs（功能大厅 / 需求列表）+ 提需求 dialog + 详情 drawer（时间线、状态管理、补充说明）
- `frontend/src/data/featureCatalog.js`：功能大厅静态数据，与 docs/user-guide/feature-catalog.md 同步维护（上线新功能两处一起改）
- 路由 `/requirements`；菜单 DEFAULT_MENU_CONFIG teacher 组 sort_order 58（缺失行启动自动落库）
- 角色判断用 `useAuthStore` 的 isAdmin/isJiaowu 决定列表 scope 与管理区块显隐

## 5. 关键边界

- 提交校验：title≥2、problem/expectation≥5 字，pydantic Field 限制
- 可见性：详情/评论接口对非提交人非管理端返回 403
- 状态合法性：不在字典内返回 400
- 留痕：提交/状态变更/补充说明全部写 requirement_log

## 6. 测试

`lesson/tests/test_requirements_api.py`（6 项）：提交落库+日志、字段校验、mine/all 可见范围与 403、详情可见性、状态流转+留痕+非法状态、评论权限。全量回归与 HEAD 基线失败集完全一致。
